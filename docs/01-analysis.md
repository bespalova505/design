# Оценка полезности для нашей базы знаний

**Рекомендация: сохранить как инженерную основу дизайн-системы и учебный reference.** Лучше всего материал решает задачи единообразия и поддержки сайта. Готовых художественно проработанных страниц и большой библиотеки секций здесь нет.

## Что действительно есть

Публичный сайт содержит четыре страницы. Главная показывает обложку и ведет в Style Guide. Style Guide: типографика, цвета, тени, кнопки, формы, иконки, каркас страницы, размеры, отступы и вспомогательные классы. Designer Guide объясняет Client-First и изменения автора. Components содержит инструкцию по Webflow и один реально выведенный блок `feature-split` с текстом, картинкой и двумя кнопками.

В тексте Components упомянуты navbar, footer и CTA. Это объясняющие примеры, а не доказательство наличия каждого такого блока в опубликованной библиотеке. В архиве они не заявлены как найденные компоненты.

## Что стоит использовать

| Прием | Практическая польза | Решение |
| --- | --- | --- |
| Значения → семантические токены → элементы | Цвет текста меняется независимо от цвета границ | Перенести принцип |
| Единая шкала spacing | Согласованные расстояния в карточках, секциях и сетках | Адаптировать под дизайн |
| Заголовки по breakpoint | Меньше расхождений между страницами и ручных мобильных правок | Использовать после исправлений |
| HTML-семантика отдельно от внешнего вида | Можно менять размер, сохраняя смысловую структуру | Использовать |
| Ясные имена компонентов и вариантов | Понятно, на что влияет изменение | Синтаксис выбирать по стеку |
| Страница Style Guide | Все элементы можно сравнить в одном месте | Делать аналог для крупных проектов |
| Свойства компонентов | Одна секция с вариантами текста, отступов и изображения | Реализовать как API компонента |
| Шесть оберток и ограничение количества классов | Удобство Navigator и селекторов Webflow | Не переносить буквально в React/Tailwind |

## Применение к нашим сайтам

Для WebWave и других агентских сайтов полезен один файл токенов для контейнеров, секций, карточек, текста и кнопок. Мобильные правки карточек и графиков тогда опираются на одну систему размеров. Это не заменяет отдельную проверку графика, данных, подписей и поведения при узком экране.

Для ресторанов и услуг можно повторно использовать каркас и контракты компонентов, сохраняя собственные палитры, типографику, фотографии и композиции каждого проекта.

Для FFL, где важны согласованные версии дизайна, такая база помогает привести выбранные элементы к общей системе. Она сама по себе не является основанием заменять утвержденную композицию типовыми блоками.

## Чего здесь недостаточно

- Нет широкой коллекции hero, pricing, отзывов, кейсов, сложных меню и графиков.
- Нет готовой React-библиотеки или исходного файла Figma.
- Нет полного набора loading/error/disabled и документированного API всех элементов.
- Нет подтверждения WCAG-соответствия и систематических тестов компонентов.
- Инструкция местами расходится с фактическим CSS.

## Актуальность

В HTML указан `Last Published: Wed Nov 08 2023`. Это дата опубликованной версии, не обязательно последней работы автора. Designer Guide говорит, что Client-First еще не поддерживает variables. В проверенной 25.09.2026 [официальной документации Finsweet уже есть Variables](https://finsweet.com/client-first/docs/variables), поэтому эту фразу нельзя переносить как актуальный факт.

Это самостоятельная модификация Client-First автором Caleb Raney, а не официальный стандарт Finsweet или современная документация всех возможностей Webflow.

## Следующие полезные действия

1. Выбрать подходящие токены из `portable/` для одного проекта.
2. Создать его Style Guide со всеми нужными состояниями и проверить реальные макеты на мобильном экране.
3. Пополнять репозиторий принятыми собственными компонентами с происхождением и примерами, отдельно от исходного архива.
